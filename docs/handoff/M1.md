**DB facts later tasks must respect (all tested)**
- DateTime storage: the adapter's default is ISO-8601 text with a `+00:00` suffix, e.g. `2026-10-15T10:00:00.000+00:00`. A `Date` bound in `$queryRaw` produces the identical text.
  - Raw `<=` comparisons match JS at millisecond boundaries.
  - Dates written by the raw claim read back exactly through the typed client.
  - Raw SQL must always bind Date parameters and never rely on `DEFAULT CURRENT_TIMESTAMP`. That default is a different format; the migration puts it on `createdAt`, which only applies to raw inserts that omit the column.
- Integers in raw queries: `$queryRaw` returns `INTEGER`-declared columns (Prisma `Int`) as a JS number, which loses precision above 2^53.
  - `BIGINT`-declared columns (Prisma `BigInt`, so every *Paise column), and untyped expressions such as SUM, COUNT and bound literals, come back as exact bigint.
  - Use `CAST(x AS BIGINT)` in raw SQL when you need exact values. COUNT(*) comes back as bigint, so wrap it with Number().
- One connection per client: the adapter keeps a single better-sqlite3 connection per PrismaClient.
  - Interactive transactions use a deferred `BEGIN` and are serialized by an in-process mutex.
  - So T03's withTx busy-retry and BEGIN IMMEDIATE test must use a second client or connection to create contention.
  - Never issue non-transaction queries on the same client while holding an interactive transaction open. They share the connection.

**Errors** (`@/lib/errors`)
- `AppError` is abstract and has `status`, `code`, `retryable`, `userMessage`, `safeDetails`, `correlationId` and `retryAfterSeconds`.
- Constructor options: `{message?, code?, userMessage?, safeDetails?, correlationId?, cause?, retryAfterSeconds?}`. You can override `code`, e.g. `new IdempotencyConflictError({code:'BATCH_CONTENT_MISMATCH'})`.
- Provider errors also take `{provider, providerCode, httpStatus}`.
- `errorToHttp(thrown, correlationId)` returns `{status, headers, body:{code, message, reference, details?}}`.
  - `details` are redacted `safeDetails` and appear only for status < 500.
  - A ZodError becomes 400 with `details.issues` as `[{path, code, message}]`.
  - Anything unknown becomes a generic 500 INTERNAL.
  - Retry-After is set from `retryAfterSeconds`.
- `errorResponse()` returns a Web `Response`; T06's `withRoute` should use it. `toAppError()` is also exported.
- Statuses to know: `TenantScopeError` is 404 and renders identically to NotFound; `LeaseLostError` is 409 and extends JobError; `DbBusyError` is 503 and retryable.

**Note for T03 and the lead:** `src/server/db/tx.ts` (T03) defines its own `DbBusyError extends Error`. `@/lib/errors` has `DbBusyError` (AppError, 503, DB_BUSY). To get a 503 from `errorToHttp`, tx.ts should throw or extend the lib class; as written, the tx error maps to a generic 500.

# T07 Job runtime and worker
## deviations
ADR-48 was appended to docs/decisions.md. I numbered it after ADR-47; if T06 also appended an ADR-48 at the same time, the lead should renumber one of them.

ADR-48 covers these points:
1. **package.json build script (non-append edit).** It now uses `tsup --entry.worker worker/index.ts`. Before, it produced dist/index.js, while start:worker and the T09 harness run dist/worker.js.
2. **Handler result contract.** Results are succeeded, deferred, retry, dead or cancelled, and any of them can carry a `finalTx`. `finalTx` runs inside the fenced settle transaction, so the domain write and the job's state change commit atomically.
3. **JobAttempt numbering.** `attemptNo` is sequential per job and independent of Job.attempts, because deferrals refund Job.attempts. A cancel is logged as FATAL with errorCode JOB_CANCELLED, since the enum has no CANCELLED outcome.

5. **Worker writes go through withTx.** The heartbeat, lease extension, claim and reaper writes all do. This is because of the one-connection-per-client adapter.
6. **Pause points are file-based across processes.** They use AURALEAD_PAUSE_DIR and AURALEAD_PAUSE_AT, and are a no-op unless NODE_ENV=test.
7. **Worker concurrency is fixed at 1.** The plan's configurable concurrency of up to 4 is not built; whichever task first needs it adds it.

Not tested: real SIGINT, SIGTERM and SIGBREAK delivery. Node on Windows cannot deliver a signal to a child process; it just terminates it. Graceful stop is instead tested through `worker.stop()` and the fixture's stdin STOP. The signal handlers are wired in worker/boot.ts.
