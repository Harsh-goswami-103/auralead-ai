# T24 Admin inspector, ambiguity resolution, global pause, backup and restore (plan §11 M3)
## deviations
ADR-64 is appended to docs/decisions.md; ADR-63 was already taken by T21. Main points:

1. **Fresh authentication instead of `withRoute({reauth: true})`.** Admin mutations accept either a password re-entry (`Session.reauthAt`) or the sign-in that created the session (`Session.createdAt`) within 15 minutes.
   - In LIVE every session is created by a password sign-in or a re-auth, so this still means a password within 15 minutes.
   - DEMO personas have no password, so `reauthAt` can never be set there. The dialog's "Sign in again as Super admin" (persona switch) counts as the fresh sign-in.
   - A stale session gets 401 `REAUTH_REQUIRED`, and the dialog re-authenticates in place.
2. **Inspector reads are treated as platform metadata.** They show redacted payloads and statuses without `adminContext`. 3. **Safe retry is decided by job type.** Nothing ever sets `Job.retrySafe`.
   - A dead non-dispatch job is requeued as is.
   - A dead dispatch job gets attempt N+1 on a new job, keyed `dispatch:operator-retry:<attemptId>`, only when its last attempt definitely did not send. An unresolved AMBIGUOUS attempt answers 409 `AMBIGUOUS_UNRESOLVED`.
   - Resend requires the typed confirm text `RESEND`.
4. **Restore copies rows instead of swapping files.**
   - It ATTACHes the backup and replaces every application table in one transaction on the live file, using the columns both schemas share.
   - `WorkerHeartbeat` and `_prisma_migrations` are kept.
   - It refuses a backup that has migrations this DB lacks, and refuses while a worker heartbeat is fresh (`--allow-running-worker` overrides).
   - Manifest, mode and sha256 checks run before the lock is written. The lock is then written first, and removed only if the transaction did not commit and the lock did not exist before.
