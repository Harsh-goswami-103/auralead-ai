### 12.5 MATERIAL decisions for the user (strict)

Only two items change permissions or legal exposure or decide whether an in-scope source yields outreach at all. Everything else is recorded in 12.6.

**M1. Extension build base (T19). Licensing and legal.**
- **A. Copy-agnostic bridge (recommended).** Ship only `extension-bridge/` + a 1-line patch guide + fixtures. Commit no vendor code. Verify locally against the original copy. The bridge honours the vendor licence gate (sync disabled when `_auth.hasValidKey !== true`).
- **B. Build and document on the license-stripped copy.** Fastest, but it depends on a paywall bypass of code with no redistribution rights. Not recommended.
- **C. Original copy with a purchased licence key.** Cleanest for production. It requires the user to hold a key, and vendor telemetry remains.
- **Recommendation:** A now, C as the production posture. **Sub-question:** may the bridge run the 50-record unlicensed tier for one local verification run? Default if unanswered: no. Report "contract verified, live extension not verified".
- **Why material:** it touches third-party licensing and whether AuraLead's docs steer customers to a modified commercial product.

**M2. Email eligibility for Maps-sourced leads (L-1). Permission and legal.**
- **A. Opt-in only.** Maps leads are scored, drafted and called manually until they opt in. Zero automated or cold email.
- **B. Opt-in, or employee-attested B2B basis (recommended default as built).** Attested leads: manual send only, unsubscribe link and suppression check mandatory, never auto-send.
- **C. B2B basis allowed for automated sends.** Not recommended (sender reputation, DPDP exposure).
- **Recommendation:** build B behind a workspace setting that defaults to A behaviour (the attestation control is hidden until the user approves B).
- **Why material:** it decides whether one of three ingestion sources produces any outbound by the product, which changes what is sold.

**Rejected as non-material:** demo/live DB split (deployment only), auto-send permission F7 (follows the PRD's role definitions), service account for Sheets (P14), AI provider PII transfer (LIVE default is the deterministic generator until a workspace configures a provider, with disclosure in Integration center and docs).

### 12.6 Consolidated recorded assumptions (non-blocking)

**Data, money and tenancy**
1. Money: `bigint` paise in the domain and Prisma `BigInt` columns. Discount at document level on the subtotal, tax on the discounted subtotal, each derived amount rounded half-up once. AT5 fixture 2,124,000 paise. Sanity cap ₹100 crore → review.
2. One configured tax line per quote. "Quotation, not a tax invoice". No GST split (P8).
3. `Quote.validUntil` default 15 days. Share link `expiresAt` ≤ `validUntil` (P16).
4. One process = one `APP_MODE` = one DB file. `Workspace.mode` is defense in depth.
5. DB, storage and backups default outside OneDrive (`%LOCALAPPDATA%\auralead\`). Boot warns if the path contains `OneDrive`.
6. Every service takes `ctx` first. A Prisma extension injects `workspaceId`. Cross-tenant access returns 404.
7. Suppression key = HMAC with a server pepper, per channel, surviving lead merge and deletion (C17).

**Jobs and dispatch**
8. Single-statement `UPDATE … RETURNING` claim. No network I/O inside a transaction. Busy retry ×3.
9. One `DispatchAttempt` outbox (C7). The reaper turns SENDING into AMBIGUOUS (C8). Operators resolve AMBIGUOUS manually with a typed reason. Missing echo ≠ not sent.
10. The eligibility function is shared by preview, approval badge and dispatch, and is re-run at dispatch inside the claim tx.
11. Stop and unsubscribe are processed synchronously in the verified webhook or unsubscribe route (C9).
12. Status precedence by rank. `failed` only at rank ≤ sent (C10).
13. Window = `lastInboundProviderAt` (monotone max) + 24 h, exclusive. Default safety margin 0 so AT9 holds. 131047 is the rescue path.
14. 131049 → review, manual retry after 24 h. 131026 → failed, no suppression (C16). The error mapping table is dated and unverified.
15. Quality RED/FLAGGED pauses WhatsApp automation only. Manual approved sends still pass the gate.

**Consent and messaging**
16. Consent is captured from mapped form or Meta consent fields with verbatim text hash (P1). Maps leads: no WhatsApp consent. Inbound creates service-window consent only (P13).
17. Email eligibility per M2 default (opt-in. Attested B2B manual-only if approved).
18. Quick-reply payloads `AL_QR_*_V1`, set per send. Text fallback. Fixed multilingual STOP list.
19. Re-opt-in after Stop needs a new ConsentRecord with evidence.
20. QUOTE request without an approved quote → draft + flagged approval, no holding message unless auto-send (P3). CALL → CallRequest + optional booking link (P4).
21. WhatsApp PDF delivery via media upload + document message. Never a localhost link (P2).
22. Templates are synced and mapped, not authored in-app (P12).
23. Unanswered-outbound count is tracked and shown. No hardcoded cap.

**AI**
24. AI proposal schema: service IDs, quantities, scope, timeline only. Price, discount and tax keys stripped, flagged, forced to review (C12).
25. LIVE: no silent fallback to local. An explicit labelled local button (C13).
26. Output policy check (currency, URLs, phones, catalog names) on every generated string. Auto-reply guard intents with fixed out-of-scope deflection.

**Quotes and public surface**
27. PDF: `@react-pdf/renderer` in a worker job from one render model. Embedded Inter TTF with U+20B9. Stored artifact with sha256 and version in the footer (C1).
28. Share token = path segment, hash stored. Invalid and revoked give the same 404. Expired and superseded give 410 (C2, C3).
29. VIEWED = beacon after 2 s of visibility, labelled "may be automated" (C4). Manual share marks SENT (P15).
30. Accept = POST with token + form nonce + Origin + expected version. Idempotent per version (C5).

**Security and ops**
31. Own email+password auth (argon2id via `@node-rs/argon2`), DB sessions, `__Host-` cookie, invite onboarding.
32. CSRF: Origin check + signed double-submit on cookie mutations. Webhooks ignore cookies.
33. Credentials: AES-256-GCM, key ring with kid, AAD = workspace|integration|field. LIVE refuses to boot without keys. DEMO setup generates one.
34. Raw body via `arrayBuffer()` for all signed webhooks. Size caps per C14.
35. Rate limits in-process. Login lockout persisted on `User` (C6).
36. SSRF-safe fetch with a pinned IP and per-hop re-validation, worker only.
37. Branding logo: raster only, re-encoded, no SVG (P7).
38. Sheets server access via service account (P14). Meta currency displayed as provided (P6).
39. Services never import `next/*` or `server-only`. Request context is explicit (5.3).
40. Injected `Clock` everywhere. `DbOffsetClock` only with DEMO + test-control flag + token. Boot refuses test control in LIVE.
41. Graph and Marketing API versions are separate config values with a check date (12.3).
42. Lead erasure is a script, not a UI. Cost estimation is a category label only (12.4).
